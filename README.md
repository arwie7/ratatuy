# Рататуй: лендинг и API заявок на бронь

Лендинг ресторанного комплекса «Рататуй» (г. Ульяновск) и API, которое принимает с сайта заявки на бронь зала.

Репозиторий один на весь проект, но архитектура не монолитная. Фронтенд собирается в статические файлы, бэкенд работает отдельным сервером. Связь между ними идёт только по HTTP, по контракту из `openapi.yml`.

## Структура

| Путь | Что лежит | Кто изменяет |
| :-- | :-- | :-- |
| `backend/` | Код API | Бэкенд-разработчик |
| `frontend/` | Проект Vite + React. Создаётся по разделу 4.2 инструкции | Фронтенд-разработчик |
| `openapi.yml` | Спецификация API v1.0 | Только бэкенд-разработчик |
| `инструкции.docx` | Инструкция для фронтенд-разработчика | Бэкенд-разработчик |
| `PRODUCT.md` | Описание продукта, подтверждённые факты, запреты на выдуманные данные | По согласованию |
| `DESIGN.md` | Дизайн-система | По согласованию |
| `analysis.md` | Анализ текущего сайта ratatuycafe.ru | По согласованию |
| `ratatuy_facts (1).md` | Факты о ресторане: адрес, залы, акции, цены | По согласованию |
| `mockup/` | Макеты, основной файл `Рататуй - макеты.html` | Дизайнер |
| `photo-sources/` | Исходники фото: `site` от ресторана, `stock` временные заглушки, источники в `sources.json` | Фронтенд-разработчик |

Папка `photo-sources/` должна лежать рядом с `frontend/`. Скрипт подготовки фото ищет её по пути `../../photo-sources`.

## Быстрый старт

Мок-сервер API из корня репозитория:

```bash
npx @stoplight/prism-cli mock -p 8080 openapi.yml
```

Фронтенд (после создания проекта по инструкции):

```bash
cd frontend
npm install
npm run dev
```

Сайт откроется на http://localhost:5173.

## Правила

- Контракт API меняет только бэкенд: правится `openapi.yml`, повышается `info.version`. Порядок описан в разделе 11 инструкции.
- Файлы `.env` с реальными значениями и файлы `*.local` не коммитятся.
- Токены, ключи CRM и пароли хранятся только на стороне бэкенда. На фронтенде есть только Base URL API и публичный ключ капчи.
